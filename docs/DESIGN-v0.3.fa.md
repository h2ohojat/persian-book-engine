# سند طراحی BookEngine نسخهٔ ۰.۳

تاریخ: 2026-10-14 · نسخهٔ آنلاین: https://claude.ai/code/artifact/a5af16d4-440c-475d-a5ba-2189a2c920a9

## خلاصه و هدف

نسخهٔ ۰.۳ کتاب را از یک فایل JSON واحد به **پوشهٔ چندفایلی** می‌برد و هستهٔ موتور را روی یک **AST درختی** و **یک schema واحد** بنا می‌کند. هدف این است که کتاب ۵۰۰ صفحه‌ای با ۵۰ فصل، بدون شکستن context هوش مصنوعی، فصل‌به‌فصل ساخته و نگهداری شود.

**در دامنهٔ ۰.۳:**

- فرمت پوشهٔ پروژه (`book.yaml`، `outline.yaml`، `chapters/*.md`، `sources/`، `fiches/`، `memory/`)
- فرمت فصل: Markdown + frontmatter + directive
- AST کتاب با inline (تأکید، پانویس، ارجاع، اصطلاح، ارجاع متقابل)
- schema واحد که validator و type از آن ساخته می‌شوند
- رجیستری بلوک‌ها به‌جای فهرست ثابت شش‌تایی
- CLI جدید پروژه‌محور + مهاجرت خودکار از BOOK v1
- رندر HTML فعلی روی AST جدید، بدون افت کیفیت

**خارج از دامنهٔ ۰.۳** (نسخه‌های بعد): PDF چاپی و EPUB، عملیات patch و سرور MCP، lint کامل، لایهٔ AI و context builder، ingest منابع PDF/Word، Studio وب.

## وضعیت فعلی (نسخهٔ ۰.۲)

هستهٔ ۰.۲ سالم است (۲۳ آزمون موفق، امنیت خوب، بدون وابستگی)، اما ساختار داده‌اش برای کتاب بلند مقیاس‌پذیر نیست. این جدول محدودیت‌هایی است که ۰.۳ حل می‌کند.

| محدودیت ۰.۲ | محل در کد | راه‌حل ۰.۳ |
| --- | --- | --- |
| کل کتاب در یک JSON تا ۲ مگابایت | `src/sdk.js` (`MAX_INPUT`) | پوشهٔ چندفایلی، یک فایل برای هر فصل |
| پرامپت کل BOOK را در خود دارد | `makePrompt` | بارگذاری فصل‌به‌فصل (پایهٔ context builder آینده) |
| بلوک‌ها مسطح و بدون inline | `engine.js` (`TYPES`) | AST درختی با گره‌های inline |
| شش نوع بلوک ثابت | `engine.js` | رجیستری بلوک |
| اعتبارسنجی دستی و جدا از schema | `validateProject` ↔ `BOOK.schema.json` | schema واحد، validator تولیدی |
| قالب editable بایت‌به‌بایت به کد موتور وابسته است | `verifyTemplate` | بررسی hash نسخهٔ موتور + بازسازی خودکار |
| ساختار فقط کتاب → فصل → بلوک | قرارداد BOOK v1 | بخش (part)، فصل، زیربخش تودرتو |
| نسخه‌بندی ندارد | پروژه git نیست | فایل‌های متنی قابل diff و آمادهٔ git |

یک ناهماهنگی کوچک هم دیده شد: `server.js` نسخه را `0.1.0` گزارش می‌کند، در حالی که موتور `0.2.0` است.

## اصول طراحی

1. **داده از موتور جداست.** AI و مؤلف فقط فایل‌های پروژه را می‌نویسند؛ کد موتور هرگز جزئی از کتاب نیست. (از ۰.۲ حفظ می‌شود.)
2. **یک منبع حقیقت برای قرارداد.** schema اصل است؛ validator، type، مستندات و پرامپت‌ها از آن مشتق می‌شوند.
3. **واحد کار = یک فصل.** هر عملیات (خواندن، نوشتن، اعتبارسنجی، build) باید بدون بارگذاری کل متن کتاب ممکن باشد.
4. **شناسهٔ پایدار برای هر چیز قابل ارجاع.** فصل، بخش، بلوک، منبع، فیش، اصطلاح و شکل شناسهٔ انگلیسی پایدار دارند. نام فایل و ترتیب ممکن است عوض شود، شناسه نه.
5. **فرمت متنی و قابل diff.** همهٔ فایل‌ها UTF-8، خط‌به‌خط خوانا و مناسب git هستند.
6. **امنیت به‌صورت پیش‌فرض.** هیچ محتوایی اجرا نمی‌شود؛ HTML خام در Markdown متن معمولی است؛ خروجی‌ها بدون `--force` بازنویسی نمی‌شوند.
7. **وضعیت انسانی در داده ثبت می‌شود و قابل جعل نیست.** تأیید منبع، طرح و فصل فیلد صریح دارد (`verifiedBy`، `approvedBy`، تاریخ) و فقط از مسیر انسانی ثبت می‌شود.
8. **هسته آفلاین و کم‌وابستگی.** اتصال به مدل زبانی هرگز شرط لازم هسته نیست.
9. **سازگاری عقب‌رو.** هر BOOK v1 معتبر بدون از دست دادن داده به پروژهٔ ۰.۳ تبدیل می‌شود و بالعکس.

## فرمت پوشهٔ پروژه

هر کتاب یک پوشه زیر `books/<book-id>/` است. ترتیب فصل‌ها فقط از `outline.yaml` خوانده می‌شود؛ پیشوند عددی نام فایل فقط برای راحتی انسان است.

```
books/my-book/
  book.yaml            شناسنامه، مخاطب، قالب، زبان، نسخهٔ قرارداد
  style.yaml           راهنمای سبک: لحن، سطح زبان، قواعد نگارشی، طول هدف
  outline.yaml         ساختار: بخش‌ها و فصل‌ها به ترتیب، با وضعیت هر فصل
  chapters/
    01-intro.md        هر فصل یک فایل Markdown
    02-basics.md
  sources/
    sources.json       کتاب‌شناسی (CSL-JSON + فیلدهای BookEngine)
    excerpts/          گزیدهٔ متن هر منبع، یک فایل txt برای هر منبع
  fiches/
    fiches.jsonl       هر خط یک فیش (برای هزاران فیش بدون فایل بزرگ)
  memory/
    glossary.yaml      اصطلاحات و معادل‌های مجاز/ممنوع
    decisions.md       تصمیم‌های تألیفی ثبت‌شده
    summaries/         خلاصهٔ کوتاه هر فصل (برای context هوش مصنوعی)
  assets/              تصویر و نمودار (در ۰.۳ فقط رزرو، رندر در ۰.۴)
  .bookengine/         cache و خروجی‌های موقت (در .gitignore)
  dist/                خروجی build
```

**نمونهٔ `book.yaml`:**

```yaml
bookEngine: 3            # نسخهٔ قرارداد پروژه
id: my-book
title: عنوان کتاب
subtitle: ""
authors: ["نام مؤلف"]
audience: معلمان دبستان
format: textbook          # textbook | workbook | trainer
language: fa
direction: rtl
versionLabel: "۰.۱"
targets: { wordsPerChapter: [1500, 3000] }
```

**نمونهٔ `outline.yaml`:**

```yaml
parts:
  - id: part-foundations
    title: مبانی
    chapters:
      - id: intro
        file: chapters/01-intro.md
        status: approved      # planned | drafted | in-review | approved
      - id: basics
        file: chapters/02-basics.md
        status: drafted
```

کتاب بدون بخش مجاز است: به‌جای `parts` یک فهرست `chapters` در بالای فایل. YAML فقط با زیرمجموعهٔ ایمن (بدون tag و anchor) خوانده می‌شود.

## فرمت فایل فصل

هر فصل یک فایل Markdown است با frontmatter از نوع YAML و directiveهای بلوکی (`:::`). این فرمت برای مدل زبانی طبیعی‌تر از JSON است، diff آن در git خواناست و مؤلف هم می‌تواند مستقیم ویرایشش کند.

```markdown
---
id: basics
title: مفاهیم پایه
objectives:
  - تفاوت فیش نقل‌قول و خلاصه را تشخیص می‌دهد.
fiches: [fiche-007, fiche-012]
---

## فیش چیست؟ {#what-is-fiche}

فیش یک یادداشت پژوهشی است که به *منبع* متصل می‌شود [@src-eco; ص ۴۵].
اصطلاح {term:fiche} در واژه‌نامه تعریف شده است.^[پانویس به همین شکل نوشته می‌شود.]
نگاه کنید به [بخش بعد](#ref:sorting).

:::callout {#basics-note kind=example}
مثال فرضی: یک دانشجو برای مقاله‌اش ۲۰ فیش می‌نویسد.
:::

:::quote {#basics-q1 source=src-eco locator="ص ۴۵، بند ۲"}
متن نقل‌قول دقیقاً مطابق گزیدهٔ منبع.
:::

:::exercise {#basics-ex1 lines=6}
سه فیش از یک مقاله بنویسید.

::rubric[هر فیش منبع و نشانی دقیق داشته باشد.]
:::
```

**قواعد:**

- **بلوک‌های ساده** از Markdown استاندارد می‌آیند: پاراگراف، تیتر (`##` تا `####`)، فهرست مرتب و نامرتب، جدول GFM.
- **بلوک‌های آموزشی** با `:::نوع {ویژگی‌ها}` باز و با `:::` بسته می‌شوند؛ نوع باید در رجیستری باشد.
- **شناسه** با `{#id}`. اگر نباشد، موتور شناسهٔ پایدار می‌سازد و با `bookengine ids --write` در فایل ثبت می‌کند. بلوک‌های آموزشی و تیترها باید شناسهٔ صریح داشته باشند.
- **ارجاع به منبع:** `[@sourceId; نشانی]` (سبک Pandoc).
- **پانویس:** `^[متن]`.
- **اصطلاح واژه‌نامه:** `{term:id}`.
- **ارجاع متقابل:** `[متن](#ref:id)`؛ شماره و عنوان مقصد هنگام build ساخته می‌شود.
- **HTML خام** پذیرفته نمی‌شود و به‌صورت متن نمایش داده می‌شود؛ لینک فقط http/https.

## مدل AST کتاب

موتور پوشهٔ پروژه را به یک درخت واحد تبدیل می‌کند و همهٔ اعتبارسنجی، transform و رندر روی همین درخت انجام می‌شود. هر گره شکل پایهٔ `{ type, id?, position, children?, data? }` دارد؛ `position` مسیر فایل و شمارهٔ خط است تا خطاها دقیق گزارش شوند.

| سطح | گره‌ها | فرزندان مجاز |
| --- | --- | --- |
| ریشه | `book` | `part` یا `chapter` |
| ساختار | `part`، `chapter`، `section` | `section` و بلوک‌ها، تا عمق ۳ برای section |
| بلوک پایه | `paragraph`، `heading`، `list`، `listItem`، `table` | inline یا بلوک (برای list) |
| بلوک آموزشی | `callout`، `quote`، `exercise` (+ هر نوع ثبت‌شده در رجیستری) | بلوک پایه |
| inline | `text`، `emphasis`، `strong`، `link`، `cite`، `footnote`، `term`، `xref` | inline |

**قواعد شناسه:**

- الگوی شناسه مثل ۰.۲ است: `^[a-zA-Z0-9][a-zA-Z0-9_-]{0,79}$`.
- شناسه در کل کتاب یکتاست، نه فقط در فصل؛ این شرط ارجاع متقابل و patchهای آینده است.
- شناسهٔ خودکار از شناسهٔ فصل + نوع + hash کوتاه محتوا ساخته می‌شود (مثلاً `basics-p-3f9a`) و با تغییر ترتیب عوض نمی‌شود.

**گره‌های جانبی** در خود `book` نگهداری می‌شوند نه در درخت متن: `sources`، `fiches`، `glossary`.

```
                          book (ریشه) ─ ─ ─ نگهداری در ریشه ─ ─ ─┐
                            │                                     ▼
                          part (اختیاری)                  ┌── جدول‌های جانبی ──┐
                            │                             │                     │
                          chapter ── frontmatter: fiches ─┼─▶ fiches            │
                            │                             │   fiches.jsonl      │
                          section (تا عمق ۳)              │                     │
                            │                             │                     │
                          blocks ──── quote: source ──────┼─▶ sources           │
  paragraph · heading · list · table                      │   sources.json +    │
  callout · quote · exercise                              │   excerpts/         │
                            │                             │        ▲            │
                          inline ──── cite ───────────────┼────────┘            │
  text · emphasis · link · footnote                       │                     │
  cite · term · xref ──────── term ───────────────────────┼─▶ glossary          │
                                                          │   memory/glossary   │
                                                          └─────────────────────┘
```

متن فقط از بالا به پایین تودرتو می‌شود؛ منابع، فیش‌ها و اصطلاحات یک بار در book نگهداری و از هر فصل فقط با شناسه ارجاع داده می‌شوند.

## schema واحد و اعتبارسنجی

اعتبارسنجی در سه لایهٔ پشت‌سرهم انجام می‌شود و لایهٔ اول مستقیماً از JSON Schema می‌آید؛ دیگر هیچ قاعدهٔ ساختاری در دو جا نوشته نمی‌شود.

1. **ساختار (schema):** هر فایل (`book.yaml`، `outline.yaml`، frontmatter فصل، `sources.json`، هر خط `fiches.jsonl`) و هر گرهٔ AST با schema خودش چک می‌شود.
2. **ارجاع‌ها (resolver):** یکتایی شناسه در کل کتاب، وجود مقصد `cite`، `xref`، `term`، فیش‌های frontmatter و فایل‌های outline.
3. **قواعد محتوایی (هشدار):** همان موارد فعلی `inspect` — منبع تأییدنشده، نقل‌قول نامنطبق با گزیده، متن جایگزین. این لایه پایهٔ lint نسخهٔ ۰.۶ است.

**انتخاب ابزار:** برای حفظ هستهٔ بدون وابستگی، validator هنگام build با Ajv از schema کامپایل و به‌صورت یک فایل JS بدون وابستگی ذخیره می‌شود (Ajv standalone). پس Ajv فقط devDependency است. typeهای TypeScript (`.d.ts`) هم از همان schema تولید می‌شوند.

**شکل خطا:** هر مورد یک شیء ماشین‌خوان است تا AI بتواند بدون حدس اصلاحش کند:

```json
{"severity": "error", "code": "ref.unknown-source", "file": "chapters/02-basics.md", "line": 14, "nodeId": "basics-q1", "message": "منبع src-ecco در sources.json وجود ندارد.", "hint": "شاید src-eco"}
```

کدهای خطا پایدار و انگلیسی‌اند؛ پیام فارسی است. سقف ۴۰ خطای فعلی برداشته می‌شود و به‌جایش خروجی بر اساس فایل گروه‌بندی می‌شود.

## رجیستری بلوک‌ها

هر نوع بلوک آموزشی یک ماژول مستقل است که در رجیستری ثبت می‌شود؛ افزودن بلوک تازه (مثل `definition` یا `summary`) دیگر به تغییر هسته نیاز ندارد.

```js
// blocks/exercise.js
module.exports = {
  type: 'exercise',
  since: 1,                       // نسخهٔ قراردادی که بلوک از آن موجود است
  attributes: {                   // بخشی از schema کل
    lines: { type: 'integer', minimum: 1, maximum: 12, default: 4 }
  },
  slots: { rubric: { optional: true } },
  children: 'blocks',             // 'inline' | 'blocks' | 'none'
  check(node, ctx) { /* قواعد اضافه، خطا با ctx.report */ },
  render: {
    html(node, ctx) { /* خروجی HTML escapeشده */ }
    // print / epub / docx در نسخه‌های بعد
  },
  formatVariants: { trainer: { label: 'فعالیت پیشنهادی برای اجرا' } },
  ai: { describe: 'تمرین با معیار اختیاری و خطوط پاسخ', example: ':::exercise {#x lines=4}\n...\n:::' }
};
```

**قواعد رجیستری:**

- schema کل پروژه از ترکیب schema هسته + `attributes` همهٔ بلوک‌های ثبت‌شده ساخته می‌شود.
- بخش `ai` مستقیماً وارد راهنمای تألیف و پرامپت‌ها می‌شود؛ پس مستندات همیشه با بلوک‌های واقعی هماهنگ است.
- در ۰.۳ رجیستری داخلی است و سه بلوک آموزشی فعلی (`callout`، `quote`، `exercise`) را دارد. بارگذاری بلوک از پوشهٔ کتاب (plugin کاربر) به دلیل امنیت تا نسخهٔ ۰.۴ عقب می‌افتد.
- `render.html` فقط رشتهٔ escapeشده از طریق helperهای `ctx` برمی‌گرداند؛ دسترسی مستقیم به متن خام ندارد.

## CLI و API

CLI جدید روی پوشهٔ پروژه کار می‌کند و همهٔ خروجی‌هایش با `--json` ماشین‌خوان هستند. دستورهای فعلی `book-cli.js` برای BOOK v1 باقی می‌مانند.

| دستور | کار |
| --- | --- |
| `bookengine new <dir>` | ساخت پوشهٔ پروژهٔ خالی از الگو |
| `bookengine validate <dir> [--chapter id]` | اعتبارسنجی کل کتاب یا یک فصل (با ارجاع‌های آن) |
| `bookengine build <dir> [--chapter id]` | ساخت HTML در `dist/`؛ فقط فصل‌های تغییرکرده دوباره ساخته می‌شوند |
| `bookengine outline <dir>` | چاپ ساختار با وضعیت، تعداد واژه و هشدار هر فصل |
| `bookengine add-chapter <dir> --id x --title … [--after y]` | افزودن فصل به outline + فایل الگو |
| `bookengine context <dir> --chapter id` | ساخت بستهٔ context برای نوشتن یک فصل (نسخهٔ اولیهٔ context builder) |
| `bookengine ids <dir> --write` | ثبت شناسهٔ پایدار برای بلوک‌های بدون شناسه |
| `bookengine import <BOOK.json> <dir>` | مهاجرت BOOK v1 به پروژهٔ ۰.۳ |
| `bookengine export <dir> <BOOK.json>` | خروجی BOOK v1 (با گزارش هر چیزی که در v1 جا نمی‌شود) |

**API برنامه‌نویسی** (ماژول `@bookengine/core`):

```ts
const project = await loadProject('books/my-book');          // فقط فراداده + outline
const chapter = await project.chapter('basics');              // بارگذاری تنبل
const report  = await validate(project, { chapter: 'basics' });
const html    = await renderHtml(project, { chapters: ['basics'] });
const ctx     = await buildChapterContext(project, 'basics', { budgetTokens: 30000 });
```

بارگذاری تنبل شرط مقیاس‌پذیری است: اعتبارسنجی یک فصل فقط همان فصل و فهرست شناسه‌های بقیه را می‌خواند. فهرست شناسه‌ها در `.bookengine/index.json` با hash فایل‌ها cache می‌شود.

## سازگاری و مهاجرت از BOOK v1

هر BOOK v1 معتبر بدون از دست دادن داده به پروژهٔ ۰.۳ تبدیل می‌شود؛ مسیر برگشت به v1 هم هست، اما چیزهایی که v1 ندارد (پانویس، بخش، واژه‌نامه) با هشدار صریح به متن ساده تبدیل می‌شوند.

| BOOK v1 | پروژهٔ ۰.۳ |
| --- | --- |
| `metadata` | `book.yaml` (`author` → `authors: […]`) |
| `sources[]` | `sources/sources.json`؛ `excerpt` → `sources/excerpts/<id>.txt` |
| `fiches[]` | `fiches/fiches.jsonl` |
| `chapters[]` (ترتیب) | `outline.yaml` بدون `parts`، `status: drafted` |
| `chapter.objectives`، `fichIds` | frontmatter فصل (`objectives`، `fiches`) |
| بلوک `paragraph` / `heading` / `list` | Markdown استاندارد با `{#id}` |
| بلوک `callout` / `quote` / `exercise` | directive `:::` با همان شناسه و ویژگی‌ها |
| `block.sourceId` + `locator` روی paragraph | ارجاع `[@id; locator]` در انتهای بلوک |
| `workflow` (یادداشت‌های مسیر در پروژهٔ کارگاه) | `memory/workflow.yaml` |

**ضمانت‌ها:**

- رفت‌وبرگشت `v1 → ۰.۳ → v1` برای هر کتاب v1 خروجی معادل می‌دهد (با آزمون روی نمونه‌های موجود).
- `verified` هر منبع عیناً حفظ می‌شود و مهاجرت هرگز آن را true نمی‌کند.
- ابزار وبی (`index.html`) در ۰.۳ همچنان با BOOK v1 کار می‌کند؛ اتصال آن به پروژهٔ پوشه‌ای کار Studio در نسخه‌های بعد است.
- مسیر `books/ai-test` به‌عنوان نمونهٔ مهاجرت در کنار نسخهٔ v1 خودش نگهداری می‌شود؛ فایل اصلی بازنویسی نمی‌شود.

## برنامهٔ اجرا و تصمیم‌های باز

اجرا در شش گام پشت‌سرهم است؛ هر گام خودش آزمون دارد و بدون شکستن ۰.۲ قابل ادغام است. قبل از گام ۱، پروژه زیر git می‌رود.

1. **schema و validator:** schema هسته برای فایل‌های پروژه و AST، ساخت validator مستقل و typeها.
2. **parser:** خواندن YAML (زیرمجموعهٔ ایمن)، Markdown + directive و inlineها به AST، با position دقیق.
3. **resolver و رجیستری:** شناسه‌ها، ارجاع‌ها، سه بلوک آموزشی در رجیستری.
4. **رندر HTML روی AST:** بازنویسی `renderBook` با حفظ CSS فعلی، به‌علاوهٔ پانویس، جدول و ارجاع متقابل.
5. **مهاجرت و CLI:** `import` / `export` و دستورهای پروژه‌محور، cache و build افزایشی.
6. **مستندات AI:** به‌روزرسانی `AGENTS.md`، راهنمای تألیف و بستهٔ ai-kit از روی رجیستری، و آزمون نهایی با یک عامل AI.

**تصمیم‌های باز (نیاز به تصمیم مالک پروژه):**

| موضوع | گزینهٔ پیشنهادی | جایگزین |
| --- | --- | --- |
| زبان پیاده‌سازی | TypeScript با خروجی JS بدون وابستگی | ادامهٔ JS خالص + JSDoc |
| parser Markdown | یک parser کوچک اختصاصی برای زیرمجموعهٔ محدود بالا | unified/remark (کامل‌تر، اما با وابستگی) |

| YAML | زیرمجموعهٔ ایمن با parser داخلی | همهٔ فراداده JSON (ساده‌تر، ناخواناتر) |
